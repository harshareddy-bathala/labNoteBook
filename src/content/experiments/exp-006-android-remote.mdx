## Abstract

Existing remote control solutions were either paid or too slow.
This experiment explores sub-100ms latency via WebRTC peer-to-peer.

## Problem Statement

No free, open-source Android remote control tool offered acceptable
latency for development use. ADB over USB doesn't work wirelessly
without significant setup friction.

## Hypothesis

WebRTC's data channels can carry input events with lower latency than
HTTP polling approaches currently used by open-source tools.

## Methodology

42-day phased roadmap: signaling server setup with coturn, Kotlin
WebSocket client on Android, Electron desktop host, input event
forwarding layer.

Paused at signaling layer. coturn configuration working.
